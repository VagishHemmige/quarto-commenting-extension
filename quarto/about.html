Contributors

issue-comments is written and maintained by Vagish Hemmige. It is released under the MIT license.

Contributing

Report a problem or suggest a change by opening an issue. Changes reach main through pull requests.

A change to the issue format has to be made in two places, buildIssue_ in apps-script/Code.gs and issueTitle and fillPreview in issue-comments.js; see How it works.

How this site is built

The site is a Quarto website in the site/ folder of the extension’s repository. _quarto.yml and index.qmd are at the top of that folder and the other pages are in site/quarto/. quarto add copies only _extensions/issue-comments/, so none of the site reaches people who install the extension.

The rendered site is not committed. On every push to main, a GitHub Action (.github/workflows/publish.yml) renders site/ with a pinned Quarto version and publishes the result to the gh-pages branch, which GitHub Pages serves. The Action can also be run by hand from the repository’s Actions tab.

The code on each page is not pasted in. Each block names a file and a line of text it starts at, and a small filter, site-tools/source-snippet.lua, reads those lines from the file when the site is rendered and links them to the same lines on GitHub. If a file is renamed or the starting line changes, the render fails with a message naming the page and file, so the site cannot silently fall out of date. The prose still has to be updated by hand when the code’s behaviour changes, in the same pull request.

To check a change before merging, run quarto render site (or quarto preview site) from the repository’s root; the output goes to site/_site/, which git ignores.
