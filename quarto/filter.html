2. Lua filter

Author

Vagish Hemmige

The filter runs once for each page Quarto renders. It decides whether the page gets commenting, settles the settings, and adds the script, the styles and the settings to the page. It does not change the page’s content.

NoteSource code

_extensions/issue-comments/issue-comments.lua

The settings it accepts

The comment at the top of the file is the reference for the issue-comments: block. Only endpoint is required.

_extensions/issue-comments/issue-comments.lua, lines 1–10

-- issue-comments: let readers highlight text and send a comment that is
-- filed as a GitHub issue by a Google Apps Script relay.
--
-- issue-comments:
--   endpoint: https://script.google.com/macros/s/XXXX/exec   # required
--   owner: Jane Doe              # who posts the issues; defaults to `author`
--   contact: https://...         # how readers reach you (URL or mailto:)
--   preview: true                # show the exact issue before posting
--   passcode: false              # ask readers for a shared passcode
--   page-button: false           # also show "Comment on this page"

Reading YAML values

Quarto hands settings to a filter as Pandoc values, not plain strings: owner: Jane Doe arrives as a list of words. str turns any value into text, and treats an empty value as missing so that contact: "" behaves like no contact at all.

_extensions/issue-comments/issue-comments.lua, lines 12–17

local function str(v)
  if v == nil then return nil end
  local s = pandoc.utils.stringify(v)
  if s == "" then return nil end
  return s
end

bool gives each on/off setting its default when it is absent. YAML true arrives as a Lua boolean, but a value written as a string ("yes", "true") is accepted too.

_extensions/issue-comments/issue-comments.lua, lines 19–24

local function bool(v, default)
  if v == nil then return default end
  if type(v) == "boolean" then return v end
  local s = pandoc.utils.stringify(v)
  return s == "true" or s == "yes"
end

first_author provides the default owner. In Quarto, author can be written as a single name, a list of names, or a list of maps with a name field (the form most templates use); this takes the first name in any of the three.

_extensions/issue-comments/issue-comments.lua, lines 27–32

local function first_author(meta)
  local a = meta["author"]
  if type(a) == "table" and a[1] ~= nil then a = a[1] end
  if type(a) == "table" and a["name"] ~= nil then a = a["name"] end
  return str(a)
end

Deciding whether the page gets commenting

The work happens in Meta, which Pandoc calls once with the page’s metadata. It returns early, leaving the page unchanged, for any non-HTML output, so PDF and Word renders of the same source are untouched.

_extensions/issue-comments/issue-comments.lua, lines 35–37

if not quarto.doc.is_format("html") then
  return meta
end

A page with no issue-comments: block, or with issue-comments: false, is also left alone. That is how a page can opt out of a site-wide setting. A block that is not a map (for example issue-comments: true) is a mistake, so it produces a warning rather than silently doing nothing.

_extensions/issue-comments/issue-comments.lua, lines 39–46

local cfg = meta["issue-comments"]
if cfg == nil or cfg == false then
  return meta
end
if type(cfg) ~= "table" then
  quarto.log.warning("issue-comments: expected a map with at least `endpoint`.")
  return meta
end

Without an endpoint there is nowhere to send comments, so the page is left alone with a warning.

_extensions/issue-comments/issue-comments.lua, lines 48–52

local endpoint = str(cfg["endpoint"])
if endpoint == nil then
  quarto.log.warning("issue-comments: no `endpoint` set; commenting is disabled.")
  return meta
end

Settling the settings

These are the six values the browser script receives. The keys are camel case (pageButton) because they become JavaScript properties. A missing contact is allowed, since readers are still told who to contact, but Quarto warns because they would have no link to follow.

_extensions/issue-comments/issue-comments.lua, lines 54–64

local settings = {
  endpoint = endpoint,
  owner = str(cfg["owner"]) or first_author(meta),
  contact = str(cfg["contact"]),
  preview = bool(cfg["preview"], true),
  passcode = bool(cfg["passcode"], false),
  pageButton = bool(cfg["page-button"], false),
}
if settings.contact == nil then
  quarto.log.warning("issue-comments: no `contact` set; readers won't see how to reach you.")
end

Loading the script and styles

add_html_dependency copies the JavaScript and CSS into the site’s site_libs/ folder and links them from the page. The version is part of the folder name there, so it should be kept in step with the manifest.

_extensions/issue-comments/issue-comments.lua, lines 66–71

quarto.doc.add_html_dependency({
  name = "issue-comments",
  version = "0.2.0",
  scripts = { "issue-comments.js" },
  stylesheets = { "issue-comments.css" },
})

Passing the settings to the page

The settings go into the page’s <head> as a global variable that the script reads when it starts. Encoding them with quarto.json.encode handles quotes and special characters. The extra replacement of </ covers the one case JSON does not: a value such as contact: "</script><script>…" would otherwise end the script tag and let the rest run as HTML.

_extensions/issue-comments/issue-comments.lua, lines 73–76

-- Escape "</" so values cannot close the script tag.
local json = quarto.json.encode(settings):gsub("</", "<\\/")
quarto.doc.include_text("in-header",
  "<script>window.ISSUE_COMMENTS = " .. json .. ";</script>")
