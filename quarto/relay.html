5. Apps Script relay

Author

Vagish Hemmige

The relay is a Google Apps Script web app that you deploy from your own Google account. It receives each comment, checks it, works out which repository it belongs to, and creates the GitHub issue as your GitHub App. One relay serves all your sites. It is the only part that holds a secret, so it is the part to read most carefully.

NoteSource code

apps-script/Code.gs

Helpers it shares with the browser script: buildIssue_ must match issueTitle and fillPreview in issue-comments.js.

Settings

All configuration lives in Script Properties, which only you can see. Changing a property takes effect on the next request, with no redeployment.

apps-script/Code.gs, lines 1–20

/**
 * issue-comments relay: receives a reader's comment from a Quarto page and
 * files it as a GitHub issue, posted by your GitHub App (shown as a bot).
 * One relay serves every site and repository you install the app on. The
 * app's private key stays here, in Script Properties, and is never sent to
 * the browser.
 *
 * Script Properties (Project Settings > Script Properties):
 *   GITHUB_APP_ID   the App ID from the app's settings page
 *   GITHUB_APP_KEY  the app's private key: the whole .pem file, pasted as is
 *   GITHUB_OWNER    your GitHub user name; a page at https://<owner>.github.io/<repo>/
 *                   posts to <owner>/<repo>
 *   REPO_MAP        optional JSON for any other site address, e.g.
 *                   {"https://example.org/plan/": "owner/repo"}
 *   PASSCODE        optional, only if you set `passcode: true` in Quarto
 *   LABEL           optional, defaults to "reader-comment"
 *   MAX_PER_HOUR    optional, defaults to 20 for each repository
 *
 * A repository receives comments only if the app is installed on it.
 */

Receiving a comment

Apps Script calls doPost for every POST to the /exec URL. Without the app’s ID and key it refuses at once.

apps-script/Code.gs, lines 22–27

function doPost(e) {
  try {
    const props = PropertiesService.getScriptProperties();
    const appId = props.getProperty("GITHUB_APP_ID");
    const appKey = props.getProperty("GITHUB_APP_KEY");
    if (!appId || !appKey) return reply_({ ok: false, error: "Commenting is not configured yet." });

The page sends JSON labelled as plain text (see Posting), so it is parsed by hand.

apps-script/Code.gs, line 29

const d = JSON.parse((e && e.postData && e.postData.contents) || "{}");

The checks then run cheapest first. A filled-in honeypot gets a fake success, so a bot has no reason to try again.

apps-script/Code.gs, lines 31–32

// Honeypot filled in: pretend success, do nothing.
if (d.website) return reply_({ ok: true });

Next the relay rebuilds the page address and works out the repository from it (below). Both steps are plain text work, with no request to GitHub, so a page that matches nothing costs almost nothing to turn away.

apps-script/Code.gs, lines 34–36

const page = cleanPage_(d.page);
const repo = page && repoFor_(page, props.getProperty("GITHUB_OWNER"), props.getProperty("REPO_MAP"));
if (!repo) return reply_({ ok: false, error: "Comments are not accepted from this page." });

The hourly limit comes before the passcode, so that every wrong guess uses up part of that repository’s allowance. Guessing a long passcode is then impractically slow. The cost is that a run of wrong guesses can block a site’s real readers for up to an hour.

apps-script/Code.gs, lines 38–41

// Counted before the passcode, so wrong guesses use up the allowance too.
if (!allow_(repo, Number(props.getProperty("MAX_PER_HOUR")) || 20)) {
  return reply_({ ok: false, error: "Too many comments right now. Please try again later." });
}

apps-script/Code.gs, lines 43–46

const passcode = props.getProperty("PASSCODE");
if (passcode && String(d.passcode || "") !== passcode) {
  return reply_({ ok: false, error: "That passcode is not correct." });
}

The name and comment are trimmed and cut to the same limits the form uses, since a request need not come from the form.

apps-script/Code.gs, lines 48–50

const name = clean_(d.name, 80).replace(/\s+/g, " ");
const comment = clean_(d.comment, 5000);
if (!name || !comment) return reply_({ ok: false, error: "Please enter your name and a comment." });

Only now does the relay contact GitHub, for a token for this repository. If the app isn’t installed there, the comment is refused with the same message as an unknown page.

apps-script/Code.gs, lines 52–53

const token = repoToken_(appId, appKey, repo);
if (!token) return reply_({ ok: false, error: "Comments are not accepted from this page." });

Then the issue is created, and the reader is sent its number and address.

apps-script/Code.gs, lines 55–57

const issue = createIssue_(token, repo, buildIssue_(d, name, comment, page),
  props.getProperty("LABEL") || "reader-comment");
return reply_({ ok: true, number: issue.number, url: issue.html_url });

Any error, including one from GitHub, is written to the Apps Script execution log for you, and the reader gets a general message, so GitHub’s response is never shown on the page.

apps-script/Code.gs, lines 58–61

} catch (err) {
  console.error(err);
  return reply_({ ok: false, error: "Something went wrong. Please try again." });
}

Which repository

The page reports its own address. cleanPage_ keeps only the scheme, host and path, lower-cases the host, and percent-encodes any character in the path that isn’t plainly safe. Brackets, parentheses and spaces therefore can’t reach the issue’s Markdown link. Plain http is accepted only for localhost, so that quarto preview can be tested through REPO_MAP.

apps-script/Code.gs, lines 69–83

/** Rebuilds the page address from its parts, so it is a plain URL that cannot
 *  break out of the issue's link. Returns "" if it is not a web address. */
function cleanPage_(v) {
  const m = /^(https?):\/\/([A-Za-z0-9.-]+(?::\d{1,5})?)(\/[^?#]*)?/.exec(clean_(v, 500));
  if (!m) return "";
  const host = m[2].toLowerCase();
  const local = /^(localhost|127\.0\.0\.1)(:\d+)?$/.test(host);
  if (m[1] === "http" && !local) return "";
  const path = (m[3] || "/").replace(/[^A-Za-z0-9._~%\-\/]/g, function (c) {
    return encodeURIComponent(c).replace(/[!'()*]/g, function (x) {
      return "%" + x.charCodeAt(0).toString(16).toUpperCase();
    });
  });
  return m[1] + "://" + host + path;
}

repoFor_ checks REPO_MAP first, longest address first, so a more specific entry wins. Each map address is cleaned the same way before comparing, so capital letters in it don’t matter, and a repository name in the map that isn’t owner/name is refused rather than used. Otherwise, a page at https://<owner>.github.io/<repo>/ belongs to <owner>/<repo>, provided <owner> is GITHUB_OWNER. The trailing / after the repository name is required, so a user site’s page such as https://<owner>.github.io/about.html is not mistaken for a repository called about.html.

apps-script/Code.gs, lines 85–101

/** Works out which repository a page's comments go to, or null.
 *  REPO_MAP entries win (longest matching address first); otherwise a page
 *  at https://<owner>.github.io/<repo>/... goes to <owner>/<repo>. */
function repoFor_(page, owner, mapJson) {
  const valid = /^[A-Za-z0-9-]+\/[A-Za-z0-9._-]+$/;
  if (mapJson) {
    const map = JSON.parse(mapJson);
    const keys = Object.keys(map).sort(function (a, b) { return b.length - a.length; });
    for (let i = 0; i < keys.length; i++) {
      const prefix = cleanPage_(keys[i]);
      if (prefix && page.indexOf(prefix) === 0) return valid.test(map[keys[i]]) ? map[keys[i]] : null;
    }
  }
  const m = /^https:\/\/([a-z0-9-]+)\.github\.io\/([A-Za-z0-9._-]+)\//.exec(page);
  if (owner && m && m[1] === owner.toLowerCase()) return owner + "/" + m[2];
  return null;
}

The address is supplied by the sender, so this decides where a comment may go, not where it came from. The last word belongs to GitHub: a repository without the app installed is refused in repoToken_.

Building the issue

buildIssue_ writes the title and body. The anchor is reduced to characters valid in an id, so it cannot break out of the link, and the page address has already been rebuilt. The name and section are escaped so they display literally; the passage and comment are left as typed, so GitHub renders any Markdown in them. Finally defuse_ runs over both title and body.

apps-script/Code.gs, lines 103–124

/** The page previews this text before posting: keep issueTitle() and
 *  fillPreview() in issue-comments.js in step with any change here. */
function buildIssue_(d, name, comment, page) {
  const section = clean_(d.section, 200).replace(/\s+/g, " ");
  const anchor = clean_(d.anchor, 200).replace(/[^A-Za-z0-9_\-:.]/g, "");
  const quote = clean_(d.quote, 1600);
  const link = page + (anchor ? "#" + anchor : "");

  const firstWords = comment.replace(/\s+/g, " ").slice(0, 60) + (comment.length > 60 ? "…" : "");
  const title = (section ? "[" + section.slice(0, 60) + "] " : "") + firstWords;

  const lines = [
    "**Submitted by:** " + escapeInline_(name) + ", via the site's comment form",
    "**Section:** [" + escapeInline_(section || "Page") + "](" + link + ")",
    "",
  ];
  if (quote) {
    lines.push(quote.split("\n").map(function (l) { return "> " + l; }).join("\n"), "");
  }
  lines.push(comment);
  return { title: defuse_(title), body: defuse_(lines.join("\n")) };
}
WarningWhere the preview and the issue can differ

The preview’s title comes from issueTitle in the browser script, and there are two small differences from the title built here:

  • The … is added here when the comment is more than 60 characters before runs of spaces and line breaks are collapsed, and in the browser when it is more than 60 characters after. A comment a little under 60 characters that contains several line breaks can get a … in the issue but not in the preview.
  • Here the section heading has runs of spaces collapsed before it is cut to 60 characters; in the browser it is used as it is.

Neither changes what a reader wrote, only how the title is trimmed. They are noted here so that the two copies can be brought back into step.

Acting as the app

GitHub Apps authenticate in two steps. repoToken_ first asks GitHub for the app’s installation on the repository; a 404 means the app isn’t installed there, and the comment is refused. It then exchanges the installation for a token that lasts an hour. The request narrows that token to this one repository and to issues, even if the app is later given more. The token is cached for 50 minutes, keyed by repository, so most comments skip both requests.

apps-script/Code.gs, lines 126–147

/** A token for one repository, from the app's installation on it. GitHub's
 *  tokens last an hour; each is cached for 50 minutes. Null if the app is not
 *  installed on that repository. */
function repoToken_(appId, appKey, repo) {
  const cache = CacheService.getScriptCache();
  const key = "token-" + repo.toLowerCase();
  const cached = cache.get(key);
  if (cached) return cached;

  const jwt = appJwt_(appId, appKey);
  const inst = github_("get", "/repos/" + repo + "/installation", jwt);
  if (inst.code === 404) return null;
  if (inst.code !== 200) throw new Error("GitHub " + inst.code + ": " + inst.text.slice(0, 300));

  const res = github_("post", "/app/installations/" + inst.json.id + "/access_tokens", jwt, {
    repositories: [repo.split("/")[1]],
    permissions: { issues: "write" },
  });
  if (res.code !== 201) throw new Error("GitHub " + res.code + ": " + res.text.slice(0, 300));
  cache.put(key, res.json.token, 3000);
  return res.json.token;
}

Both requests are signed with a JSON Web Token (JWT) that appJwt_ makes from the app’s private key. It says which app is asking (iss), and is valid for nine minutes, starting a minute in the past in case Google’s and GitHub’s clocks differ slightly. GitHub accepts at most ten.

apps-script/Code.gs, lines 149–157

/** The short-lived signed token (JWT) that identifies the app to GitHub. */
function appJwt_(appId, appKey) {
  const b64 = function (s) { return Utilities.base64EncodeWebSafe(s).replace(/=+$/, ""); };
  const now = Math.floor(Date.now() / 1000);
  const input = b64(JSON.stringify({ alg: "RS256", typ: "JWT" })) + "." +
    b64(JSON.stringify({ iat: now - 60, exp: now + 540, iss: String(appId).trim() }));
  const sig = Utilities.computeRsaSha256Signature(input, pkcs8_(appKey));
  return input + "." + b64(sig);
}

Apps Script’s computeRsaSha256Signature only accepts a key in PKCS#8 form (BEGIN PRIVATE KEY), but GitHub’s downloads are PKCS#1 (BEGIN RSA PRIVATE KEY). The two hold the same key; PKCS#8 just wraps it with a note saying it is an RSA key. pkcs8_ adds that wrapping, so the .pem file can be pasted as it is, without converting it first with openssl. It also rebuilds the line breaks, which are often lost when the key is pasted into a Script Property.

apps-script/Code.gs, lines 159–175

/** Apps Script signs only with a PKCS#8 key ("BEGIN PRIVATE KEY"), but GitHub
 *  hands out PKCS#1 ("BEGIN RSA PRIVATE KEY"). This accepts either, with or
 *  without its line breaks, and returns PKCS#8. */
function pkcs8_(pem) {
  const pkcs1 = /BEGIN RSA PRIVATE KEY/.test(pem);
  let der = Utilities.base64Decode(pem.replace(/-----[^-]+-----/g, "").replace(/\\n|\s/g, ""))
    .map(function (b) { return b & 255; });
  if (pkcs1) {
    const len = function (n) { return n < 128 ? [n] : n < 256 ? [0x81, n] : [0x82, n >> 8, n & 255]; };
    const rsaAlgorithm = [0x30, 0x0d, 0x06, 0x09, 0x2a, 0x86, 0x48, 0x86, 0xf7, 0x0d, 0x01, 0x01, 0x01, 0x05, 0x00];
    const inner = [0x02, 0x01, 0x00].concat(rsaAlgorithm, [0x04], len(der.length), der);
    der = [0x30].concat(len(inner.length), inner);
  }
  const body = Utilities.base64Encode(der.map(function (b) { return b > 127 ? b - 256 : b; }));
  return "-----BEGIN PRIVATE KEY-----\n" + body.replace(/(.{64})/g, "$1\n").replace(/\n$/, "") +
    "\n-----END PRIVATE KEY-----\n";
}

Creating the issue

createIssue_ posts the issue with the repository’s token and the reader-comment label (or your LABEL). Anything other than 201 Created is treated as a failure.

apps-script/Code.gs, lines 177–182

function createIssue_(token, repo, issue, label) {
  const res = github_("post", "/repos/" + repo + "/issues", token,
    { title: issue.title, body: issue.body, labels: [label] });
  if (res.code !== 201) throw new Error("GitHub " + res.code + ": " + res.text.slice(0, 300));
  return res.json;
}

github_ makes every call to GitHub’s REST API. muteHttpExceptions lets the code read GitHub’s error instead of Apps Script throwing its own.

apps-script/Code.gs, lines 184–200

function github_(method, path, bearer, body) {
  const res = UrlFetchApp.fetch("https://api.github.com" + path, {
    method: method,
    contentType: "application/json",
    headers: {
      Authorization: "Bearer " + bearer,
      Accept: "application/vnd.github+json",
      "X-GitHub-Api-Version": "2022-11-28",
    },
    payload: body ? JSON.stringify(body) : undefined,
    muteHttpExceptions: true,
  });
  const text = res.getContentText();
  let json = null;
  try { json = JSON.parse(text); } catch (err) { /* not JSON */ }
  return { code: res.getResponseCode(), text: text, json: json };
}

The hourly limit

allow_ keeps, for each repository, the times of the requests in the past hour, in the script cache. A request is allowed if there are fewer than MAX_PER_HOUR of them. Because the window rolls with each request, rather than resetting on the hour, no 60-minute span can take more than the limit. The script lock stops two simultaneous requests from both reading the same list and both going through.

apps-script/Code.gs, lines 202–218

/** At most `max` requests per repository in any 60 minutes. */
function allow_(repo, max) {
  const lock = LockService.getScriptLock();
  lock.waitLock(5000);
  try {
    const cache = CacheService.getScriptCache();
    const key = "rate-" + repo.toLowerCase();
    const hourAgo = Date.now() - 3600000;
    const times = JSON.parse(cache.get(key) || "[]").filter(function (t) { return t > hourAgo; });
    if (times.length >= max) return false;
    times.push(Date.now());
    cache.put(key, JSON.stringify(times), 3700);
    return true;
  } finally {
    lock.releaseLock();
  }
}

Google may clear the cache early, which resets the count, so this is a brake rather than a guarantee.

Small helpers

clean_ turns anything into a trimmed string with Unix line endings, cut to a maximum length.

apps-script/Code.gs, lines 220–222

function clean_(v, max) {
  return String(v == null ? "" : v).replace(/\r\n?/g, "\n").trim().slice(0, max);
}

defuse_ puts an invisible zero-width space into three things GitHub would otherwise act on. After @, it stops a comment from notifying a user. After the # of owner/repo#12, and inside github.com in a link to another repository’s issue, pull request or discussion, it stops GitHub from adding “mentioned this” to someone else’s issue. The text looks the same. A plain #12, which can only refer to the same repository, is left alone.

apps-script/Code.gs, lines 228–233

function defuse_(s) {
  return s
    .replace(/@(?=[A-Za-z0-9])/g, "@​")
    .replace(/([A-Za-z0-9][A-Za-z0-9-]*\/[A-Za-z0-9._-]+)#(?=\d)/g, "$1#​")
    .replace(/github\.com\/(?=[^\s\/]+\/[^\s\/]+\/(?:issues|pull|discussions)\/\d)/gi, "github​.com/");
}

escapeInline_ puts a backslash before Markdown’s special characters, so a name such as *Jane* shows as typed.

apps-script/Code.gs, lines 235–237

function escapeInline_(s) {
  return s.replace(/([\\`*_\[\]<>])/g, "\\$1");
}

reply_ sends every answer as JSON.

apps-script/Code.gs, lines 239–242

function reply_(obj) {
  return ContentService.createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}

Updating the deployment

After changing Code.gs, use Deploy → Manage deployments → Edit → Version: New version. That keeps the same /exec URL. New deployment gives a new URL, which every site using the relay would then need.
